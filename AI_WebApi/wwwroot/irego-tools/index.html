统一请求

POST /api/ai/patients/tools/{tool_name}。服务 Bearer、登录主体和短期签名凭证由已认证业务后端绑定，模型不生成身份参数。

{
  "system_context": {
    "user": "authenticated-subject",
    "conversation_id": "conversation-example",
    "patient_identity": {"type": "project_user_id", "value": "7"},
    "current_business_id": 1,
    "identity_context_token": "business-backend-issued-proof"
  },
  "data_scope": "all_tenants"
}

patient_identity.type 接受 project_user_id 或 login_name，value 保留原字符串及前导零。user 表示登录主体；只有数字 user 的旧格式不再接受。手机号不作为公开查询主键。

两种范围

data_scope行为
all_tenants（默认）查询本人已确认账号的康复记录。机构未知时明确标注，不猜测归属。
current_tenant验证当前机构资格，再按每条记录所属机构过滤。历史机构依据不足的记录不纳入。

query_scope 说明实际范围及覆盖不足；record_tenant 返回医院/卫生中心名称、归属状态、依据和名称来源。tenant_segments 按记录时间保留 A→B→A 的来源段，不推断连续治疗期。

发现、分析和报告

  1. 调用 resolve_patient_identity 和 GET catalog 确认身份范围及可用工具。各家族共用匿名 patient_ref。
  2. 通过 context/history 发现记录，只使用当前范围返回的 session_ref 或 assessment_ref。切换范围后重新发现。
  3. IReGo 单次分析通过 selector=latest_usable/session_ref；纵向分析使用 selection_mode=latest_count/recent_ordinal_range/date_range，最多 10 个报告位置。
  4. 生成图片前，先取得同范围、同选择条件的分析。IReGo 使用 detail_level=standard、quality_detail=summary；将 source_snapshot 原样绑定到报告请求的 expected_source_snapshot。
  5. 直接展示报告的 display_markdown。image_url 的 access_grant 查询参数必须保留，最长有效 5 分钟且不超过身份凭证有效期。过期后重新调用工具取得新地址。

旧裸 patientId 查询、旧 robot/project 身份映射以及旧公开图片下载入口已移除，不发布第二套 /v2/tools 路由。

规范响应

根 contract_version 为 2.0.0。单次 IReGo 统一使用 report_blocks、overview.report_block_count；能力评价使用 basic_evaluation。报告和图表保留实际记录所属机构。

success 表示可用结果，partial 同时说明覆盖或质量限制，unavailable 表示当前无法提供该结果。未接入或无法核实归属的来源不等同于患者没有记录。

步道历史数据没有可靠机构字段，默认不按相同数字猜测患者。仅纳入业务核实的来源/记录绑定；当前机构视图还要求记录级机构依据。

部署与验证

配置至少 32 字节的 PatientAccess__IdentitySigningKey，并由业务登录后端签发最长 900 秒的 patient_identity_v2 凭证。缺少配置返回 503，无效凭证返回 401。业务签名密钥不进入模型或普通日志。

本版按现有 project 和 dbbuniessuser 读取，不执行新库迁移。当前完成构建与隔离单元验证；按要求未执行 smoke test。
