IR患者康复工具 · 2.0.0

身份、本人账号与记录机构分别校验

契约 2.0.0；返回工具说明

三项可信依据

  1. 服务 Bearer 确认调用来源。
  2. 业务后端签发的 identity_context_token 绑定登录主体、入口 project 账号、患者角色、当前机构和有效期。
  3. 服务端复核账号状态、患者角色和中间表关系，再确定允许读取的本人账号及记录范围。

单有服务 Token、患者编号或“由 Dify 自动填写”的声明都不能替代患者授权。模型只选择前序结果中已返回的记录引用。

同人关联

LoginName 仅用于唯一定位入口账号。同号候选须有业务确认的 phone_binding_hash，且通过身份资料一致性检查；冲突、疑似测试数据或未经核实的历史账号不自动扩展。核实后的历史同人账号可使用 ConfirmedAccountGroups 配置。

所属机构

project 计划链路从 dbrehaplan.BusinessId 读取记录机构；不使用当前登录机构、用户当前 BusinessId 或设备当前机构覆盖历史。名称来自当前字典时明确标注；名称缺失与归属未知分别展示。

all_tenants 保留本人所有权已确认但机构未知的记录；current_tenant 要求记录所属机构可验证。账号切换不改变历史记录的机构标注。

引用与报告

引用和缓存绑定执行主体及范围摘要。身份/角色/租户关联变化后重新授权；切换范围后不能重用另一范围的引用。报告下载凭证仅适用于指定图片，有效期最多 5 分钟，访问时再次核对当前绑定。

验证边界

本次使用编译、隔离 SQLite 和纯控制器单元测试检查授权、过滤、机构分段和报告下载授权。未启动服务、未做 HTTP 探测、未做 smoke test；调用方需要同步改造后再部署。
